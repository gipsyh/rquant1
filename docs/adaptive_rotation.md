# 自适应轮动策略

实现：[adaptive_rotation.rs](../src/strategy/adaptive_rotation.rs)。命令：

```bash
RUST_LOG=debug cargo run -- bt --end 20260928 adaptive-rotation
```

默认开始日期为 2020-01-01，初始资金 100,000 元。公共回测参数放在策略名之前，策略参数放在之后；完整参数用 `cargo run -- bt adaptive-rotation --help` 查看。调试日志记录本次解析后的完整策略配置。

## 规则

1. 使用信号当日已生效的 `399101.XSHE` 指数成分，排除上市不足 120 个自然日、当日无行情、ST、退市整理期或历史不足的股票。
2. 按最近 120 根个股日线的平均成交额升序排列。前 100 只用于观察市场趋势，前 20 只用于选股。
3. 候选池内分别计算原始收盘价升序排名和 20 日复权收益升序排名，综合分为两项名次各占 50%。相同因子值取平均名次；综合分相同优先低成交额，再按股票代码排序。反转窗口采用 **20 根个股实际日线**，停牌日不计入根数。
4. 目标持有 6 只。已有持仓仍在综合排名前 12 名时优先保留，然后按排名补足。保留股票不每日重新等权。
5. 风险信号为观察池中 `复权收盘价 / 最近 5 根日线均价 - 1` 的中位数。初始空仓；严格超过 0.005 时开启，严格低于 0 时关闭，边界及区间内保持上次状态。关闭时对全部持仓发出卖单。
6. 收盘决策、次日开盘执行。卖单和买单分为先后两个批次；新增股票等分买入批次可用现金的 95%。该比例控制新增买入预算，持仓期间会随价格漂移。

默认每天重新选股。`--rebalance-days` 可延长正常调仓间隔；风险切换、ST 退出和失败委托重新计算不等待正常调仓。失败卖单仍可能因停牌、跌停等原因继续无法成交。观察池不足时不生成新的风险信号；已有风险关闭状态继续清仓，已有风险开启状态保留持仓并处理已知 ST 状态。

`--max-trend` 是默认关闭的可选过热阈值。启用后，趋势达到或超过该值时优先关闭风险；趋势回落到阈值以下且再次满足入场条件时重入。它必须大于 `--entry-band` 且小于 1。该选项已覆盖单元测试，未作为本次默认正式回测结果使用。

引擎遇到持仓进入退市整理期仍可能直接终止，沿用框架原有退市处理限制。

## 研究范围与限制

研究检查了低成交额、反转、价格、波动率、市值、估值、分红及若干风险过滤组合，进行了数千个配置的快速筛选。2024 年以后的数据也被反复查看，因此上述分段仅为诊断，不能称为未参与选择的样本外验证。参数和规则存在选择偏差，历史夏普不保证未来表现。

市值与估值探索使用 Tushare [daily_basic 官方接口](https://tushare.pro/document/2?doc_id=32) 的 92 个历史月末快照，只在快照日期之后使用；这部分结果未优于当前候选，未接入正式策略。最终策略直接使用现有日线、复权因子和历史指数成分接口。探索脚本及原始下载保留在被 Git 忽略的 `report/research/`，正式运行不依赖这些 Python 文件。

过热退出的快速筛选曾得到约 2.42–2.51 的夏普，但尚未完成对应配置的 Rust 全区间核验，默认保持关闭；这些估算不作为已验证绩效。

沿用框架的零滑点、无容量限制、固定历史税率、复权收益近似等假设，详情见 [README 回测口径](../README.md#回测口径与限制)。没有修改引擎绩效算法、交易费用或成交规则来提高指标。
